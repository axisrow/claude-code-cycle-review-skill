# CLAUDE.md

## Project Overview

Claude Code plugin providing the `/cycle-review` skill — an automated PR review loop with **two modes**. On first run it onboards the user to pick which review bots they have (`@claude`, `@codex`, or both) and a default review **mode** (`cloud`/`local`). Plans a multi-PR merge strategy when several PRs are open, verifies each PR implements its linked issue 100% before requesting review (step 3), gets a review, triages comments/findings (FIX / SKIP / HALLUCINATION / IRRELEVANT / CONFLICTING / ALREADY_FIXED / UNVERIFIED), applies fixes, and repeats until approval.

- **Cloud mode** (default, original behavior): pings the configured GitHub bots in a PR comment, waits for them via `wait-for-reviews.sh`, then runs autonomously through CI + squash-merge.
- **Local mode**: the built-in `/review` command (invoked via the **`Skill` tool**, read-only single-pass; its review lands as an assistant message in the skill's own context and is read from there by judgment — NOT a PR comment, no fixed format) reviews the PR — and when `@codex` is in the reviewers list it *also* runs Codex locally via the codex plugin's `codex-companion.mjs adversarial-review --background --base <PR baseRefName> --json` (run in the background, in parallel; findings merged before triage; **fail-closed** if Codex is configured but unavailable, or if `/review` returns no review at all). No bot ping, no GitHub wait. Each round's merged findings (both `/review` and Codex) are persisted to `~/.claude/cycle-review/runs/<PR>-round<N>.json` so the step-9 cleanup pass can re-read across rounds. It records each round's verdicts as a PR summary comment, fixes, commits, and pushes, but is **review-only on merge**: it never merges on its own; the user triggers merge explicitly.

## Structure

```
.claude-plugin/plugin.json            # plugin manifest
skills/cycle-review/SKILL.md          # skill definition
skills/cycle-review/wait-for-reviews.sh  # unified reviewer-wait driver (step 5)
skills/cycle-review/verify-comment.sh    # local triage-summary comment gate (step 6)
skills/cycle-review/resolve-companion.sh # Codex companion path resolver (steps 0.2 + 4.1)
tests/                                   # bash tests, one per script
```

## Key Details

- A single skill, `/cycle-review`, invoked directly (no slash-command alias)
- Requires `gh` CLI authenticated with GitHub, plus `jq` for reading/writing the onboarding config
- **Two review modes (step 1):** `cloud` (default) and `local`. Selection precedence: a leading `local`/`cloud` (or `--local`/`--cloud`) token in `$ARGUMENTS` overrides the saved `mode`; with neither, default to `cloud` (backward-compatible, incl. v1 configs without a `mode` field). The token is stripped before PR-number parsing, same as `onboard`. Local mode reviews with the built-in `/review` command, plus Codex locally when `@codex` is configured (parallel, merged, fail-closed), posts a triage-summary comment per round, and **never auto-merges** (review-only on merge — user triggers it). Cloud mode is the original autonomous-through-merge path
- Onboarding (step 0): optional, asks an `AskUserQuestion` for reviewers (multi-select `@claude`/`@codex`, used by cloud) + default mode (single-select `cloud`/`local`). Stored globally at `~/.claude/cycle-review/config.json` (`{"reviewers": [...], "mode": "cloud", "version": 3}`). v1/v2 configs stay valid (mode absent ⇒ cloud). Re-run with `/cycle-review onboard` (legacy: `--onboard` / `--reconfigure`). Cloud steps 4–5 are driven by the reviewers list — never hardcode `@claude`. **Dev mode:** if the resolved codex plugin's `version` (read from `plugin.json` next to the companion script, not the companion's file path — a manual dev symlink can put the fork at a path with no `-fork/` segment) contains `-fork`, a second `AskUserQuestion` asks for default Codex model (`spark`/`sol`/`terra`/`luna`) + effort (`medium`/`high`/`xhigh`/`max` — picker capped at 4 per Claude Code's limit; the rare `none`/`minimal`/`low`/`ultra` stay reachable via `--effort` per-run override), stored as `codex_model`/`codex_effort` and passed to the companion every round. Upstream `codex` — no dev mode, unchanged.
- Both configured → one ping comment starting `@claude @codex`; single reviewer → just that mention
- **Step 5 waiting is a deliberately dumb driver** `skills/cycle-review/wait-for-reviews.sh` (~50 lines). It just `sleep`s a fixed window (`WAIT`, default 300s) then probes that the API is reachable, and prints one line: `DONE` (wait elapsed, API up → triage) or `ERROR` (sustained API outage → stop, don't merge). It does NOT detect who finished, parse bodies, track per-reviewer state, or resume — ALL interpretation (who replied, relevance, hallucination, Claude usage-limit) happens in the step-6 triage, which reads every comment from every surface itself. No state file, no `RESET`. Run via Bash with `run_in_background: true` + `dangerouslyDisableSandbox: true` (leading foreground `sleep` is blocked; `sleep` inside the backgrounded script is fine). This replaced an over-engineered ~290-line version whose completion-detection/round-scoping/resume machinery kept generating its own bugs
- Claude usage-limit is handled in triage, not a separate step: a usage-limit message means "Claude did not review" (not a finding); proceed on Codex if it reviewed, else stop. Never wait for the limit to reset
- Safety invariant lives in step-6 finalize: never merge unless at least one reviewer actually reviewed this round; `ERROR` from step 5 or bot silence ⇒ stop (an empty triage is not approval)
- Completeness gate (step 3): before requesting review, verify each PR implements its linked issue's design 100% (read the issue, checklist the design, verify the diff, close gaps test-first). Bots check code correctness, not completeness against the issue — don't burn a review round on a half-finished PR
- Deferred minor findings (every genuine `SKIP` plus reasonable nice-to-haves, gathered from EVERY prior round, de-duped, excluding `HALLUCINATION`/`IRRELEVANT`/`CONFLICTING`/`ALREADY_FIXED`/`UNVERIFIED`) are applied **inside step 7**, in the same commit/push as that round's `FIX`es — not after a clean round. Step 9 (final gate) is therefore normally a **no-op**: it just re-checks nothing was left un-applied and posts the roll-up summary, then goes straight to CI (step 10). This exists so a clean review round never gets trailed by a cosmetic cleanup commit that would otherwise force an unnecessary extra review round (the bug this fixed: Codex approving in round 1 while Claude still had a `FIX`, followed by a genuinely clean round 2, was previously followed by a pointless round 3 because step 9's old cleanup-after-clean-round pass moved the head and re-triggered review)
- Max 3 cycles per PR (one cycle = one steps 4–8 round **that triaged at least one `FIX`**). If a 3rd cycle still has `FIX` verdicts, stop instead of looping a 4th time: summarize the open findings and ask the user to narrow scope (move some out of scope into a follow-up issue/PR, or rethink). Cap only bites when findings persist; a clean 1st/2nd round finalizes normally. **Cycles vs. re-reviews:** a return to step 4 triggered by step 9 (the rare case where it did have something to apply) or step 10 (a CI fix) is a re-review of the same cycle, not a new cycle — it doesn't consume the 3-cycle budget, and is capped at 2 re-reviews per cycle before stopping
- **Review→merge binding (steps 4–11):** **local mode is for your own PRs only** (`author == @me`); foreign PRs are forced to cloud mode, where the vendor runner provides isolation/atomicity the skill can't. Each review round binds to **both sides of the diff** — `ROUND_HEAD_SHA` + `ROUND_BASE_REF` + `ROUND_BASE_SHA` (base advancement is normal repo activity and invalidates a round). A minimal review-binding record (`{author, reviewed_head_sha, reviewed_base_ref, reviewed_base_sha}`) is persisted at step 6's terminal success, `rm`'d before any cleanup edit / round restart, and re-verified (author+head+base unchanged) before step 11 merges with `gh pr merge --match-head-commit` (atomic; no plain-merge fallback). Cloud reviewer output is `commit_id == ROUND_HEAD_SHA` + object-ID floor (defeats reuse of an old review of the same SHA). Local executable evidence (reproduction) is for **trusted/own PRs only** — the conservative-execution trust gate applies.
- All `gh` commands need `dangerouslyDisableSandbox: true` (sandbox blocks TLS to api.github.com)
- Skill uses Agent tool for comment triage (subagent)
- **Local Codex (step 4):** when `@codex` is in the reviewers list, local mode also runs Codex. Companion path resolution lives in `skills/cycle-review/resolve-companion.sh` (one line on stdout, exit always 0: a path, `NOT_FOUND`, or `OVERRIDE_BROKEN <path>`), called by both step 0.2 (dev-mode detect) and step 4.1 — SKILL.md must call it, never re-derive the rules inline. It resolves from `~/.claude/plugins/installed_plugins.json` (the canonical plugin→installPath index). Filter hard — the chosen script runs with `dangerouslyDisableSandbox: true`, so a wrong pick can execute an unrelated plugin: only entries whose plugin name is exactly `codex` or `codex-fork` (anchored allowlist, not substring), only `scope: "user"` (never `local`/`project` scoped to another repo), newest `lastUpdated` first (actively installed version, not a file-cache leftover), then probe both layouts (`<installPath>/plugins/codex/scripts/codex-companion.mjs` for the fork meta-plugin, `<installPath>/scripts/codex-companion.mjs` for the direct upstream) and take the first existing. Never hardcode the source namespace or path layout. An explicit escape hatch exists for installs the manifest can't see (e.g. a manual dev symlink under `~/.claude/skills/` never registered via `/plugin install`): if `CODEX_COMPANION_PATH` is set and points at an existing file, it is used directly and the manifest resolver is skipped entirely — this is deliberately the *only* fallback (no scanning of `~/.claude/skills/*/plugin.json` or similar heuristics: an env var the user set themselves is explicit authorization for a `dangerouslyDisableSandbox` launch; inferring "this looks like codex" from an arbitrary skills-directory entry is not). A set-but-broken override fails closed as `OVERRIDE_BROKEN <path>` — the manifest is NOT consulted, so a typo can't silently run a different executable; that outcome must stay distinguishable from `NOT_FOUND` in the user-facing message. The old name `CYCLE_REVIEW_CODEX_COMPANION_PATH` still works for one release as a deprecated fallback (stderr warning) and is then removed. (`${CLAUDE_PLUGIN_ROOT}` can't be used here — it points at the owning plugin, cycle-review, not codex.) It reviews the PR diff with `adversarial-review --background --json --base <baseRefName>` (`baseRefName` from `gh pr view`; works because local mode is checked out on the PR branch — companion can't review a PR by number, only local git). **`--background` is a turn-budget selector here, not a detach:** review commands always block in-process and print the final JSON to stdout (only the companion's `task` command truly enqueues); the flag switches the codex-fork from its 110s foreground turn budget (which killed every complex-diff review — the budget ducks a host Bash-tool SIGKILL that never fires inside a `run_in_background` bash) to the background budget (600s idle + 45-min hard ceiling). Upstream codex parses and ignores the flag (no turn timeouts). `--wait` is a no-op for review commands and must not be used — it leaves the fork on the 110s budget. **Dev mode (codex-fork):** the resolved plugin's `version` containing `-fork` unlocks `--model`/`--effort` flags, sourced from config (`codex_model`/`codex_effort`) with per-run `--model`/`--effort` override; upstream `codex` gets neither flag. If config has `codex_model`/`codex_effort` set but the resolved plugin isn't a `-fork` build, the skill logs a one-line note that they're being ignored this round (config/plugin mismatch, not fail-closed). Run in the background (`Bash run_in_background: true` + `dangerouslyDisableSandbox: true`) in parallel with `/review`. Output parsed from **`.result.findings`** (not `.findings`), mapped to the common finding shape (`file`→`path`, `line_start`→`line`, severity critical/high→critical else minor), tagged `reviewer: codex`, merged with `/review`'s findings (read by judgment from the free-form prose `/review` writes as an assistant message in the skill's own context — `/review` posts nothing to GitHub; invoked via the Skill tool; no fixed format, no steering, no parser), then triaged (Codex claims re-verified, not trusted). Fail-closed: empty path (codex plugin not installed — say so, don't suggest `codex login`), non-zero exit (installed but not logged in — ask for `codex login`), OR the `Skill` `/review` call erroring / producing no review at all ⇒ stop, never fall back to `/review` alone, never finalize on silence
- Language: skill prompts in English, responds in user's language
